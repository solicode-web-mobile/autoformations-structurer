# Capacité : Rédaction Compacte

## 🎯 Objectif
Produire une documentation technique qui va droit au but, en limitant le texte au strict nécessaire pour qu'un développeur comprenne instantanément l'utilité et le fonctionnement.

## 📝 Règles de Rédaction

1. **Structure Imposée (Maximale)** :
   - **Titre (H1)** : Nom de l'outil, du composant ou du script.
   - **Principe (1 phrase)** : Ce que ça fait et le besoin auquel ça répond.
   - **Fonctionnement (Puces)** : Les grandes étapes de fonctionnement (3 à 5 puces maximum).
   - **Utilisation (Code)** : La ou les commandes / exemples de code concrets pour s'en servir.

2. **Style de Rédaction** :
   - Utiliser des phrases courtes et affirmatives.
   - Privilégier les listes à puces pour énumérer des concepts.
   - Éviter absolument le jargon inutile ou les longues introductions.

3. **Ce qu'il faut EXCLURE formellement** :
   - Les "Bonjour" ou textes d'accueil.
   - L'historique des versions et la genèse du projet.
   - L'explication détaillée de la logique algorithmique interne (la doc est pour l'utilisateur, pas le mainteneur, sauf si spécifié).
   - Les fioritures de mise en forme complexes (tableaux géants, etc.).
