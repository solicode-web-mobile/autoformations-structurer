Je proposerais une configuration où **les données pédagogiques restent simples et déclaratives**, tandis que **Jekyll/Liquid construit automatiquement les relations et la navigation**.

L’idée centrale est de ne pas traiter `Compact`, `Normal` et `Détaillé` comme trois contenus pédagogiques différents, mais comme **trois représentations d’un même objet `Tutoriel`**.

### Architecture cible

```text
                    FORMATION WEB
                         │
        ┌────────────────┼────────────────┐
        │                │                │
     Missions        Sessions         Domaines
        │                │
   Compétences           │
        │                │
     Domaines ───────────┘
        │
        ↓
       UA
        │
        ↓
     Tutoriel
        │
   ┌────┼────┐
   ↓    ↓    ↓
Compact Normal Détaillé
```

### 1. Je recommande 6 collections

```text
_missions/
_competences/
_domaines/
_uas/
_sessions/
_tutos/
```

Mais **seules `sessions` et `domaines` constituent la navigation principale**.

Les autres objets sont des données pédagogiques accessibles par contexte.

### 2. Chaque objet possède un code métier stable

```text
Mission     → M1
Compétence  → C.111
Domaine     → D.111.1
UA          → UA.111.11
Tutoriel    → T.111.111
Session     → S1
```

La relation devient donc :

```text
M1
└── C.111
    └── D.111.1
        └── UA.111.11
            ├── T.111.111
            │   ├── compact
            │   ├── normal
            │   └── detaille
            │
            └── T.111.112
                ├── compact
                ├── normal
                └── detaille
```

### 3. Front Matter minimal

#### UA

```yaml
---
title: "Analyser un besoin existant"
code: "UA.111.11"
competence: "C.111"
domaine: "D.111.1"
sessions:
  - "S1"

tutos:
  - "T.111.111"
---
```

#### Tutoriel

```yaml
---
title: "Analyser un besoin existant"
layout: tuto

tuto_id: "T.111.111"
version: "normal"

ua: "UA.111.11"
domaine: "D.111.1"
competence: "C.111"

sessions:
  - "S1"
---
```

Les versions `compact`, `normal`, `detaille` reprennent **exactement les mêmes métadonnées**.

---

## 4. Je recommande de ne pas mettre la version dans la logique pédagogique

Le système doit considérer :

```text
T.111.111
```

comme l'objet.

Puis :

```text
T.111.111 + compact
T.111.111 + normal
T.111.111 + detaille
```

comme ses trois représentations.

C'est beaucoup plus propre que de créer :

```text
T.111.111-C
T.111.111-N
T.111.111-D
```

car cela casserait l'idée d'un tutoriel unique.

# 5. Navigation de l'apprenant

Je recommande le flux suivant :

```text
Session S1
    ↓
UA.111.11
    ↓
T.111.111
    ↓
version courante
```

Au premier accès :

```text
version = normal
```

L'apprenant clique ensuite :

```text
[ Compact ] [ Normal ] [ Détaillé ]
```

Puis le site mémorise :

```javascript
localStorage.setItem('tuto_version', 'compact');
```

À partir de là :

```text
T.111.111 → Compact
T.111.112 → Compact
T.112.111 → Compact
```

jusqu'à ce que l'apprenant change son choix.

---

# 6. Même principe pour la taille du texte

Je créerais un second réglage indépendant :

```text
[ A− ] [ A ] [ A+ ]
```

avec par exemple :

```javascript
localStorage.setItem('text_size', 'large');
```

L'expérience devient donc :

```text
Préférences apprenant
├── Niveau de lecture
│   ├── compact
│   ├── normal
│   └── detaille
│
└── Taille du texte
    ├── small
    ├── normal
    └── large
```

Ces préférences sont globales au site.

# 10. Navigation entre tutoriels

C'est ici que je ferais une vraie amélioration par rapport à la proposition initiale.

Le bouton :

```text
Tutoriel suivant →
```

ne doit **jamais pointer directement vers la version Normal**.

Il doit d'abord connaître la préférence :

```text
version courante = compact
```

et construire :

```text
T.111.112 / compact
```

Ainsi la navigation précédente/suivante de Just the Docs devient également cohérente avec le choix pédagogique.

C'est une règle importante :

> **Toutes les navigations internes vers un tutoriel doivent respecter la version sélectionnée par l'apprenant.**

# 11. UA avec plusieurs tutoriels

Une UA peut être :

```text
UA.111.11
├── T.111.111
└── T.111.112
```

La page UA doit afficher :

```text
UA.111.11 — Analyser un besoin existant

1. T.111.111 — Identifier le besoin
2. T.111.112 — Décrire les fonctionnalités
```

Mais les liens sont dynamiques :

```text
si version = compact
→ /T111111/compact/
→ /T111112/compact/

si version = normal
→ /T111111/normal/
→ /T111112/normal/
```

Le contenu reste exactement celui produit par le Skill de rédaction.

Le layout s'occupe uniquement de l'expérience de lecture.

# 13. UI/UX : règle à ajouter au Skill

Je formaliserais une règle générale :

> **Toute nouvelle interface doit être conçue d'abord pour la compréhension et la navigation de l'apprenant, puis pour l'esthétique.**

Les composants doivent être :

```text
Lisibles
Simples
Cohérents
Accessibles
Responsive
Peu nombreux
```

Le site doit donner la priorité au contenu pédagogique.

# 14. Architecture logique finale

Je recommande finalement cette séparation :

```text
                    DONNÉES
                       │
       ┌───────────────┼───────────────┐
       ↓               ↓               ↓
    Référentiel     Pédagogie      Ressources
       │               │               │
 Mission            Session         Tutoriel
   ↓                  ↓               ↓
Compétence           UA          3 versions
   ↓                                  │
Domaine                         Compact / Normal /
   ↓                             Détaillé
```

Et côté expérience :

```text
              APPRENANT
                  │
        ┌─────────┴─────────┐
        ↓                   ↓
 Niveau de lecture      Taille texte
        │                   │
 Local Storage          Local Storage
        │                   │
        └─────────┬─────────┘
                  ↓
           Navigation cohérente
```

### Ma recommandation principale

Je partirais donc sur **un modèle "Tutoriel unique + trois représentations"**, avec :

```text
M1
 ↓
C.111
 ↓
D.111.1
 ↓
UA.111.11
 ↓
T.111.111
 ├── Compact
 ├── Normal
 └── Détaillé
```

et **un seul état utilisateur global** dans `localStorage` pour la version et la taille du texte.

C'est, à mon avis, la configuration la plus simple à maintenir avec Jekyll/Just the Docs tout en restant parfaitement alignée avec votre modèle pédagogique.
